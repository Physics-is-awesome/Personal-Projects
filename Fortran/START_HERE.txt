THE PROBLEM YOU HAD
───────────────────

Your original mesh design used an ICOSAHEDRON.

    An icosahedron is a surface polyhedron:
    ┌──────────────────────────────────────────┐
    │  - 20 triangular faces                   │
    │  - Vertices lie on sphere S²             │
    │  - ONLY triangulates the SURFACE         │
    │  - Does NOT fill the 3D volume          │
    └──────────────────────────────────────────┘

    BUT: DG method requires VOLUME integrals ∫_K f(u) dV
    
    A tetrahedron is a 3D volume element:
    ┌──────────────────────────────────────────┐
    │  - 4 vertices, 6 edges, 4 faces         │
    │  - Fills 3D space                        │
    │  - Has well-defined volume = |det(J)|/6  │
    │  - Supports affine coordinate mapping   │
    │  - Enables DG basis functions            │
    └──────────────────────────────────────────┘

THE FORMULAS YOU NEED
─────────────────────

TETRAHEDRON VOLUME
    Given vertices x₁, x₂, x₃, x₄:
    
    J = [x₂-x₁ | x₃-x₁ | x₄-x₁]    (3×3 matrix)
    V = |det(J)| / 6

AFFINE MAPPING
    x(ξ) = x₁ + J·ξ
    
    where ξ ∈ reference tetrahedron [0,1]³ with ξ₁+ξ₂+ξ₃ ≤ 1

GRADIENT TRANSFORMATION
    ∇_x u = (J⁻ᵀ) ∇_ξ u

REFERENCE QUADRATURE
    ∫_Kref f(ξ) dξ ≈ Σq wq f(ξq)

PHYSICAL QUADRATURE
    ∫_K f(x) dx ≈ Σq f(xq) · wq · |det(J)|
    
    where xq = x₁ + J·ξq


TYPICAL DG LOOP
───────────────

FOR each element e = 1..nelem
  GET J(e), det(J(e)) from geometry_t
  FOR each quadrature point q = 1..nqp
    xq = x₁ + J·ξq                        ← map to physical
    u(xq) = Σi u_i·φ_i(ξq)               ← evaluate solution
    ∇u(xq) = (J⁻ᵀ)·Σi u_i·∇φ_i(ξq)       ← evaluate gradient
    F = flux(u, ∇u)                      ← compute flux
    S = source(u, x)                     ← compute source (use r = |x|)
    residual += [basis·F - ∇basis·F + basis·S] · wq · |det J|
  END
END


WHY THIS DESIGN?
────────────────

Before (wrong):
  type mesh_t
    ! mixed everything together
    x(:,:), conn(:,:),        ← topology
    vol(:), J(:,:,:),         ← geometry
    det_J(:), inv_J(:,:,:),
    element_radius(:),        ← WRONG for 3D
    qp(:,:,:), w(:,:),        ← basis/quadrature
    basis(:,:,:,:),
    u(:,:,:),                 ← state
    ... 50+ fields
  end type
  ! Can't test anything independently
  ! Can't recompute geometry separately
  ! Confuses topology with DG data

After (correct):
  mesh_t        ← 4 fields (topology)
  geometry_t    ← 4 fields (derived)
  reference_t   ← reference element
  basis_t       ← basis functions (future)
  state_t       ← solution (future)
  ! Each module is testable
  ! Each module has clear purpose
  ! Easy to extend/replace

QUESTIONS?
──────────

Q: How do I add face connectivity?
A: Later, in geometry.F90. For now, focus on volume integrals.

Q: Can I use a structured mesh?
A: Yes, if it's tetrahedral. Gmsh can generate structured hex meshes
   and convert to tets, or use unstructured Delaunay.

Q: Do I really need element_radius?
A: NO. Evaluate r(x) = √(x²+y²+z²) at quadrature points when needed.

Q: Should I use P0 or P1 or higher order?
A: Start with P0 (piecewise constant, 1 coeff per element).
   Easy to verify conservation. Then extend to higher order.

Q: How do I know if my geometry is correct?
A: Check: Total volume = 4πR³/3 for sphere of radius R.
   Also: Jacobian determinant is always positive for correct orientation.
